# ADR 0033: local receipt history capability checks

Status: implementation candidate; independent review required.

Receipt delivery adds durable collections and terminal states whose meaning must survive a reader change. A hash-valid log alone does not establish that a reader understands them. The compatibility check scans complete history, including superseded states, before the current service replays or writes its startup lease. The existing single-writer directory claim remains held continuously through this check, replay and service lifetime. Refusal closes the service and releases its claim without rewriting the journal. Ordinary ledger assessment remains mandatory and unchanged.

Fixed source profiles identify prior source `8e632340b70f32389a4fa3149023b0ed68dbe7c0` and receipt-capable billing source `774e46b2ca5fc9b5758eaba909450156b27d88c9`. These are source capability descriptions, not image attestations. Arbitrary profile names or caller-supplied capabilities cannot authorize a target. Current startup uses its compiled receipt-capable profile; requests and environment cannot select the legacy profile. Unknown collection names, inner operation kinds, receipt statuses or additional receipt/contact/envelope fields refuse compatibility; this is a bounded receipt check, not a general database schema validator or migration engine.

The local CLI takes the same exclusive directory lock and verifies the full local journal hash chain before assessing receipt history. It requires an existing regular journal, refuses a symlink/FIFO/device, caps the read at 256 MiB and emits only fixed reason codes and hashes. It does not query the ledger or verify an image. Missing history is not equivalent to an empty verified journal. No journal content, identifiers, email or body is printed.

The CLI releases its lock before returning. Its result is an immediately expiring diagnostic snapshot, never a scan-to-launch permit. A following writer can change the history. Current startup independently rechecks under its own continuously held ownership claim. Cooperating Finance writers honor the flock; same-user arbitrary filesystem edits and volume replacement are outside this advisory-lock guarantee.

Already-shipped images cannot execute a guard added later. Neither this CLI nor a marker prevents direct Railway GUI rollback to an old image. External deployment enforcement remains a release blocker: an exact compatible rollback artifact must be independently verified and incompatible targets excluded before receipt activation. This slice introduces no deployment control, new rollback entrypoint, mail provider, restoration path or activation permission. Never make a reader boot by dropping records, resetting attempts/deadlines/keys, or truncating the journal. Prefer a verified compatible roll-forward target; operator recovery follows the runbook and never bypasses integrity checks.
