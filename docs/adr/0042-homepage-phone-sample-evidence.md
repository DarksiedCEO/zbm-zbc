# ADR 0042 — Attributed homepage phone sample evidence

Status: implemented for independent review; no production or legal-compliance certification.

## Decision

New entity-check runs record `homepage_phone_observation` schema `homepage-phone-sample/1` independently of all-page Organization/LocalBusiness comparisons. The closed states are `found`, `not_found_in_sample`, and `unknown`, with fixed reasons. Only explicitly selected `/` with readable successful HTML FetchResult provenance qualifies. Requested and final URL must exactly equal the configured root URL; no scheme, www, port, path, fragment or host aliases are inferred. Missing provenance or a redirect to a different URL is unknown. No extra fetch, scope expansion or fetch/SSRF-policy change occurs.

The observation examines only the existing parser's first 20,000 extracted raw-HTML text characters. It requires a successful parse and consistent sample/total-length metadata. A full ten-digit canonical number, optionally prefixed by NANP country code and supported spaces/dots/hyphens/parentheses, must have complete token boundaries; longer alphanumeric identifiers do not count. A candidate ending at a truncated sample boundary is not positive because its unseen continuation is unknown. Numbers after or across the cutoff are not found in the sample, not proven absent from the page. Missing canonical telephone, unread homepage, invalid metadata and unsupported provenance remain unknown. This is neither visual visibility nor CSS/JavaScript/browser, phone-link clickability, whole-page or sitewide absence evidence.

The old `phone_in_visible_text` fact retains its historical all-page semantics and is not homepage proof. All-page markup comparisons remain unchanged. New runs stop generating the old `PHONE_NOT_IN_VISIBLE_TEXT` finding and use `HOMEPAGE_PHONE_NOT_IN_TEXT_SAMPLE` only for a valid nonmatch. Unknown homepage coverage prevents an otherwise fully checked entity area from appearing fully checked; valid markup evidence remains independently available.

## Rendering and compatibility

An ABSENT new field selects the exact legacy renderer/2 presentation, including its existing limitations and wording. Historical audit data and recorded document hashes are never rewritten or backfilled. A PRESENT field selects renderer/3 even when malformed or its schema is unknown; such evidence is explicitly UNKNOWN/not checked, never silently downgraded to a clean legacy result. Renderer validation checks closed state/reason, URL agreement and sample metadata; output uses existing URL privacy projection and HTML/Markdown escaping, no sampled body or arbitrary reason text.

New HTML and Markdown include sample state, safe checked location, limits and distinctions from visual/whole-page evidence. The service records the actual selected renderer version from the model. Existing `REPORT_CHANGED` protection remains: retries compare generated bytes with the recorded hash and refuse changed documents without replacing history. Rendering and provider acceptance do not establish report delivery or human review.

## Validation and limits

Tests cover other-page masking, unread/unselected homepage, actual FetchResult/parser and owned loopback redirect chains, malformed metadata, complete phone boundaries, sample cutoffs, script/JSON-LD/href-only text, new/unknown schema rendering and actual record/idempotency behavior over a retained legacy fixture. Existing legacy golden files are unchanged; deliberate retained-view changes still refuse replay. Test evidence and original failures are retained privately. No real client/provider traffic is used. Unrelated markup-absence location behavior, visual browser evidence and broader SEO completion remain out of scope.
