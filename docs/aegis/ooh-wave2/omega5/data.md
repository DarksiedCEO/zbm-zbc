### C7 detail: does each key new test's claim hold on the real Rust ledger?
How the faults were made. On the real ledger nothing can be "forgotten" in-process, so I produced each fault one of these ways: by editing the ledger's own JSONL while it is stopped; by switching the service to another real ledger; by POSTing anchors through the candidate's HttpLedgerClient; or by raising an exception inside _commit at the exact step (a simulated process death; the API answered 500), then opening a fresh instance on the same data dir.
- Anchor lost on the ledger: HOLDS. The real ledger fails closed first. A tail truncation is refused by its head checkpoint ("holds 29 entries but the head checkpoint records 30"). Deleting a middle anchor is refused as ChainBroken at seq 4. So "middle anchor lost" exists only on the FakeLedger; on the real ledger ooh then gets "the ledger cannot be read" and writes 503. After the operator accepts the truncation with the ledger's own one-shot LEDGER_ALLOW_RESET=<binding> and a normal restart (ledger verify true), ooh reports "local log line 15 has no matching anchor on the ledger", a write → 503 INTEGRITY_UNVERIFIED, and the restart is still blocked. Wrong target: a fresh empty real ledger → "local log line 1 has no matching anchor", write 503, 0 events written to it. A ledger holding another ooh log's anchors with a fresh data dir → "another ooh log", write 503.
- Unanchored local line: HOLDS. Appended in-process → "line 14 has no matching anchor", write INTEGRITY_UNVERIFIED, 0 anchors added, restart still blocked (503). Written into ooh_log.jsonl while stopped → start integrity false, health degraded, write 503. Side note: after a restart the forged tenant IS in memory and served on reads (the M-2 class).
- Disk-pending line with its anchor: HOLDS. Hand-placed line: appended (+1), applied, pending file gone, nothing set aside, next write 201. The real crash path (anchor recorded on the ledger, process dies before append, new instance) → appended at start, applied, anchors == lines (14/14), restart diff [], read-back [].
- Disk-pending line without its anchor: HOLDS. Set aside (pending.discarded == the line), not applied, not appended. After the late anchor is POSTed to the real ledger, the next check appends and applies it, clears discarded, anchors == lines. The real crash path (process dies after write_pending, before the anchor POST) → new instance sets it aside; the late anchor lands; it is revived; anchors == lines 14/14; read-back [].
- Vouched only by another department or event type: HOLDS. A seo log_anchor, or an ooh "note", with the SAME id and payload hash is accepted by the real ledger.
