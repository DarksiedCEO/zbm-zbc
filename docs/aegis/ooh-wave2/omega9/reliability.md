## 3. file_problem / write-path failure handling (probe_fp.py, probe-fp-3.13.txt; 3.13; the suite's own tests cover shrink/FIFO/symlink/device on both)
Method: patch os.open/fstat/pread/close on a 3-line log, track every fd the log opened and whether it was closed, compare /dev/fd count. 24 cases x (file_problem, append_prepared). Results (all with leaked_fds = [] and fd count delta 0):
- os.open raising EIO, ENOENT, ELOOP, EAGAIN/EWOULDBLOCK (same errno on macOS and Linux), EACCES, EMFILE, ENXIO, EINTR, EROFS: file_problem returns "cannot be read (<OSError class>)" (ENOENT with lines in memory: "differs"); append_prepared raises StoreWriteError "local log open failed". Fail closed in all.
- fstat EIO, pread EIO/EAGAIN/EINTR: file_problem "cannot be read"; write path StoreWriteError, file untouched.
- Real file states: symlink to identical bytes (ELOOP), FIFO with no writer, directory, unix socket, chmod 000, deleted file: file_problem reports a problem, write refused. No blocking.
- File shrinks between fstat and the first pread: both refuse (short read -> mismatch). File grows after fstat: file_problem reads only len(memory) bytes and returns None (the foreign tail is seen at the next check, whose fstat size differs); the write path writes at offset and leaves the foreign tail (carried F-R1 INFO, below).
- MemoryError and KeyboardInterrupt in pread: propagate, fd closed (the `finally`).
- os.close raising EIO (after the real close): see F1.
fd leak: none; every os.open on the log path is closed on every exit (try/finally for fstat, S_ISREG refusal, pread error, BaseException). The size is compared before the read and a sparse 256 MiB file is refused without reading (tracemalloc test passes; memory not measured by me beyond the suite).

## Findings
- F1, LOW, class CLEANUP_SKIPPED (fail closed). Claim: file_problem's `finally: os.close(fd)` (store.py:~262-267, the `finally` after the inner try/except) is outside the except OSError, so an OSError from close() propagates out of file_problem and out of verify_integrity (service.py:336, not wrapped); in 99569bd the `with open(...)` close error was inside the try and reported as "cannot be read". Repro: probe_fp.py case "os.close raises EIO" -> "RAISED OSError: [Errno 5] close EIO" for file_problem. Consequence: the exception leaves the lock cleanly (with-block); at startup (service.py:140) it stops the start, on the audit/job route a 5xx, and in _gate (service.py:282) a 5xx; all fail closed, no write allowed, no state change. Needs close() to fail with EIO on a regular file (NFS/quota class), not seen on local APFS/ext4. The same close in append_prepared (pre-existing at 99569bd, line 229) would leave the line on disk but not in memory (OSError is not StoreWriteError, so _commit's handler is skipped); the next write/check then adopts/rolls forward. Falsifier: a test patching os.close to raise after closing that expects "cannot be read" from file_problem.
- F2, LOW, class TIMEOUT_UNBOUNDED (latent, test-only). The write-path half of test_edges_integrity_check_does_not_block_on_a_fifo (test_aegis_h1_edges.py, `r = _new_tenant(h, "fifo-w")`) runs in the main thread with no timeout, and the write-path open has no O_NONBLOCK (store.py:~202); it relies on O_RDWR not blocking on a FIFO (true on Linux and macOS, undefined by POSIX). Today: no hang (observed). A future regression would hang the whole suite instead of failing it. Falsifier: run the test with the write-path open mutated to O_WRONLY and see it hang.
- F3, LOW (hygiene), class RESOURCE_EXHAUSTION (test residue). Tests leave a 256 MiB apparent-size sparse file and two symlinks (one to /dev/zero) in pytest's tmp dir for the last three runs. 16 KB real use on APFS; on a filesystem without sparse support the same test would write 256 MiB per run (and keep three runs). Repro: leakcheck lines in seq30-*.txt. Falsifier: `du` of the basetemp on the target CI filesystem under 1 MB.
- F4, INFO, class RACE (carried F-R1, unchanged): a foreign append between the compare and the pwrite is overwritten at the offset and leaves a tail, detected at the next write/check (probe: "wr grows after fstat -> WROTE", then next check differs). Needs a hostile writer with filesystem access and exact timing.
- No new RACE, DUPLICATE_EXECUTION, NON_IDEMPOTENT_RETRY, CRASH_UNRECOVERED, PARTIAL_FAILURE_TORN_STATE, fd leak or ReDoS found. No retry loop or timeout in the delta.
